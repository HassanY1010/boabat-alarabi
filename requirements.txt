# بوابة العربي

## Voice-Based Vehicle Plate Recognition & Wanted Vehicle Detection System

**Document Type:** Complete Software Requirements & AI Development Specification
**Version:** 1.0
**Target:** Production-Ready Mobile Application
**Primary Platform:** Android
**Language:** Arabic / RTL
**Primary Speech Accent:** Egyptian Arabic
**Secondary Accent:** Yemeni Arabic
**Primary Objective:** Extremely fast and highly accurate voice-based vehicle plate capture and wanted-plate detection.

---

# 1. Executive Summary

"بوابة العربي" هو تطبيق موبايل متخصص في تسجيل أرقام لوحات السيارات باستخدام الصوت أثناء العمل الميداني.

المستخدم لا يريد كتابة رقم اللوحة يدويًا.

بدلًا من ذلك:

1. يفتح التطبيق.
2. يضغط على زر الميكروفون.
3. يبدأ التطبيق بالاستماع بشكل مستمر.
4. المستخدم ينطق أرقام وحروف اللوحات بشكل طبيعي وسريع.
5. التطبيق يحول الكلام إلى بيانات لوحة.
6. يقوم التطبيق باستخراج:

   * حروف اللوحة.
   * أرقام اللوحة.
7. يعرض اللوحة فورًا في قائمة النتائج.
8. يسجل موقع GPS لحظة التقاط اللوحة.
9. يبحث عن اللوحة في البيانات المستوردة من Excel.
10. إذا كانت اللوحة مطلوبة، يظهر تنبيه بصري وصوتي قوي وفوري.
11. تستمر الجلسة في الاستماع دون الحاجة إلى الضغط على الميكروفون لكل لوحة.
12. عند انتهاء العمل يستطيع المستخدم إنهاء الجلسة وتصدير جميع النتائج إلى Excel.

# 2. أهم شرط في المشروع

## Accuracy & Speed Are The Core Product

هذا التطبيق لا يعتبر ناجحًا لمجرد أن:

* الميكروفون يعمل.
* Speech-to-Text يعمل.
* النص يظهر على الشاشة.
* Excel يتم استيراده.
* API يعمل.

النجاح الحقيقي هو:

> المستخدم ينطق لوحة سيارة بسرعة وبلهجة مصرية طبيعية، والتطبيق يلتقط اللوحة ويحولها إلى حروف وأرقام صحيحة خلال وقت قصير جدًا، ثم يحدد فورًا إذا كانت اللوحة موجودة في قائمة المطلوبين.

أي Feature أخرى تعتبر ثانوية مقارنة بهذه الوظيفة.

# 5. Never Promise 100% Accuracy

النظام يجب تصميمه لتحقيق أعلى دقة ممكنة، لكن لا يجوز افتراض أو ادعاء 100% Accuracy بشكل مطلق.

الدقة تعتمد على:

* جودة الميكروفون.
* ضوضاء الشارع.
* سرعة النطق.
* المسافة من الهاتف.
* اللهجة.
* الشبكة.
* Speech Engine.
* طريقة نطق الأرقام.
* تشابه الأصوات.
* اختلاف نطق الحروف.

لذلك يجب تعريف:

## Target Accuracy

ويتم قياسها عمليًا بواسطة Dataset حقيقي.

الهدف المقترح:

* Plate Recognition Accuracy ≥ 99% في الظروف المستهدفة.
* Wanted Match Accuracy ≥ 99.9%.
* Zero false positive alert target قدر الإمكان.
* Latency منخفض جدًا.

ولكن الرقم النهائي يجب تحديده بعد اختبار الـ PoC.

# 11. Plate Normalization

يجب توحيد اللوحة قبل البحث.

مثال:

```text

ا-هـ-ر 2753

```

```text
AHR2753
```

لكن يجب الاحتفاظ بالصيغة الأصلية للعرض.

# 20. Confidence Score

كل نتيجة يجب أن تحتوي داخليًا على Confidence.

مثال:

```text
0.99 → High Confidence
0.95 → High Confidence
0.85 → Medium
0.70 → Low
```

لا يجب عرض الرقم للمستخدم بالضرورة.

لكن النظام يستخدمه لتحديد:

* Accept automatically.
* Retry recognition.
* Ask for confirmation.

---

# 21. Context-Aware Recognition

يجب استخدام بيانات Excel للمساعدة في التصحيح.

مثال:

النظام سمع:

```text
AHR275B
```

لكن في Excel توجد:

```text
AHR2753
```

إذا كانت احتمالية المطابقة عالية، يمكن للنظام ترجيح:

```text
AHR2753
```

لكن يجب تسجيل أن النتيجة كانت normalized/corrected.

---

# 22. Never Silently Make Dangerous Corrections

لا يجوز أن يقوم النظام بتغيير لوحة إلى لوحة أخرى بدون منطق واضح.

خصوصًا في Wanted Detection.

لذلك:

```text
Raw Transcript
Parsed Plate
Normalized Plate
Matched Plate
Correction Confidence
```

يجب الاحتفاظ بها.

# 104. Final AI Coding Instructions

You are a Senior Flutter, Backend, Speech Recognition and Database Engineer.

Do not treat this project as a normal CRUD application.

The core challenge is real-time Arabic speech recognition of vehicle license plates, especially Egyptian Arabic speech in noisy outdoor environments.

Before implementing the complete product:

1. Build a speech recognition proof-of-concept.
2. Test multiple STT providers.
3. Test real Egyptian Arabic recordings.
4. Measure plate-level accuracy.
5. Measure end-to-end latency.
6. Build a robust Arabic plate normalization and parsing layer.
7. Only proceed to full application development after the speech pipeline reaches the agreed practical accuracy target.

The application must use continuous listening.

Do not require the user to press the microphone for every plate.

The parser must support:

* Arabic letters.
* Arabic numerals.
* Western numerals.
* Spoken Arabic numbers.
* Egyptian pronunciation variants.
* Configurable plate formats.
* Noise words.
* Partial speech results.

The application must integrate:

* GPS.
* Excel import.
* Multiple Excel sheets.
* Dataset versioning.
* Wanted vehicle matching.
* Strong audio alerts.
* Visual alerts.
* Haptic alerts.
* Session management.
* Local offline storage.
* Background synchronization.
* Excel export.

Never hardcode the customer's Excel structure.

Never expose API secrets in the mobile application.

Never use a single raw STT transcript as the final truth without normalization and validation.

Never silently convert an uncertain plate into a wanted plate.

Every critical operation must be measurable and testable.

The final implementation must prioritize:

1. Accuracy.
2. Latency.
3. Reliability.
4. Wanted-match correctness.
5. Offline resilience.
6. Security.
7. Maintainability.

The UI is secondary to speech accuracy and real-world usability.
